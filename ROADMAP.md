## Цель проекта
Создание автономного ассистента для мобильной стратегии *War & Order* (`com.camelgames.superking`), работающего через Wi-Fi ADB на реальном Android-устройстве (TECNO CL8, разрешение 1080x2436) с использованием компьютерного зрения и OCR. Проект остаётся в образовательных/тестовых рамках: без модификации APK, памяти и сетевого трафика.

## 🛠 Этап 7: Стабилизация 2.0 и городской автопилот (2026-10-22 →)

Цель этапа: сделать городской цикл предсказуемым и безопасным, связать
подтверждённые действия с моделью мира и только затем переходить к кампании
и бою.

### 7.1. ActionGuard: пересъёмка вместо отмены (P0) — реализовано

**Проблема.** Движок передаёт задаче кадр, пока классификация и OCR занимают
2–4 с. При пороге свежести 3 с задача отменяла безопасное действие на кадре
возрастом 4.5 с. Это не защищало от ошибки, а ломало городской цикл.

**Решение.**
- `ActionGuard.is_actionable()` проверяет наличие кадра, среднюю яркость
  (`> 2`) и возраст (`<= 8 с`).
- `ActionGuard.refresh_if_stale()` при устаревшем или тёмном кадре делает
  **один** свежий снимок. Если свежий кадр тоже непригоден — действие
  отменяется.
- `BaseTask.ensure_screen()` — единая точка входа для задач.
- `BuildingUpgradeTask` и `CityGiftsTask` используют `ensure_screen()`.

**Файлы:** `src/action_guard.py`, `src/tasks/base_task.py`,
`src/tasks/building_upgrade.py`, `src/tasks/city_gifts.py`.

**Критерии готовности:**
- [x] Устаревший кадр → ровно один свежий снимок → действие продолжается.
- [x] Тёмный кадр → свежий снимок; если снова тёмный — отмена.
- [x] Свежий кадр тоже устарел → отмена без клика.
- [x] Тесты на все три случая.

### 7.2. Таймер улучшения → WorldModel (P0) — реализовано, ждёт live

**Проблема.** После подтверждения улучшения world model не знал, что
строитель занят, и не мог показать ближайшее событие. Если создавать таймер
по факту тапа, можно записать ложное событие при неактивной кнопке.

**Решение.**
- Перед подтверждением OCR читает:
  - название здания (заголовок панели);
  - уровни `LV.N → LV.M`;
  - таймер над синей кнопкой (`11:52`).
- `src/time_parser.py::parse_duration()` разбирает `11:52`, `1:02:03`,
  `11.52`, `11 мин 52 сек`, `1 ч 2 мин 3 с`, `1152` и отвергает
  невозможные значения.
- `world.start_upgrade(name, duration, current_level)` вызывается **только
  после исчезновения панели** «Требуется».
- Уровень с панели авторитетен: после завершения таймера он станет
  `current_level + 1`.
- Если таймер не распознан, таймер мира не создаётся; в лог пишется
  предупреждение.

**Файлы:** `src/tasks/building_upgrade.py`, `src/time_parser.py`,
`src/world_model.py`, `src/bot_engine.py`, `config.yaml`.

**Критерии готовности:**
- [x] OCR эталонной панели: `wall`, `LV.4 → LV.5`, `11:52` = 712 с.
- [x] Офлайн-flow: только радиальная и синяя кнопки; серая не нажимается.
- [x] После успешного подтверждения строитель занят, таймер записан,
  уровень здания = `current_level`.
- [ ] Живая проверка: в `world_model.json` появился занятый строитель и
  `timer_end ≈ now + duration`.
- [ ] После истечения таймера уровень здания увеличился на 1.

### 7.3. Живая проверка улучшения (P1)

Стена Замка уже `LV.5` при замке `LV.5`; следующий уровень может требовать
более высокого замка/лорда. Нужно найти другое доступное здание.

**План:**
1. В городе выбрать ферму/лесопилку/казарму с доступным улучшением.
2. Снять панель, проверить OCR названия/уровней/таймера.
3. Временно включить `building_upgrade` в `config.yaml`.
4. Запустить `main.py --duration 90`.
5. Проверить `memory_bank/world_model.json`: `builders.builder_1.busy=true`,
   `target` совпадает, `timer_end` в будущем.
6. Выключить задачу, если проверка не завершена.

**Риски:** неверное имя здания → таймер запишется на чужое здание; лечится
явным `name` в `spots` и OCR-проверкой заголовка.

### 7.4. Soak-тест 10–15 минут (P1)

**Цель:** убедиться, что экран не гаснет, ADB не отваливается, задачи не
зацикливаются и guard не отменяет всё подряд.

**Критерии:**
- 10–15 минут без `adb offline` и без чёрных кадров.
- Нет повторяющихся `unknown_screen` и `recovery` каждые несколько секунд.
- `CityHarvest`/`CityGifts` не чаще разрешённого интервала.
- В логе нет нажатий зелёных кнопок/оплаты.

### 7.5. Вход в кампанию (P1)

**Проблема:** нижний баннер `(400, 1930)` не открывает Королевскую Дорогу.
Нужен проверенный путь до карты кампании.

**План:**
1. Проверить верхнюю кнопку с молотом, вкладку в «Задании», золотой свиток
   на карте мира.
2. Для каждого варианта — шаблон/OCR-якорь, а не слепой клик.
3. Записать переход в `screens_manifest.md` + `ui_coordinates.yaml`.
4. После входа — классифицировать `campaign_map` и этапы.
5. Только затем делать `CampaignEntryTask`.

**Зависимости:** уверенная классификация `royal_road` и `campaign_map`,
безопасный возврат в город.

### 7.6. Быстрый поток кадров для боя (P2)

**Проблема:** `adb pull` ~1.8 с; для боя нужны кадры 5–10 FPS.

**Варианты:**
- scrcpy + виртуальный дисплей/окно;
- minicap (требует сборки под ABI устройства);
- локальный сокет на Windows (адаптация `android-harness`).

**Критерии:** стабильный поток ≥ 5 FPS, возможность немедленной остановки,
отсутствие вмешательства в трафик/память игры.
