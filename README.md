# WaO_bot — Android RTS Automation Sandbox 🤖🎮

Экспериментальный фреймворк для автоматизации мобильной стратегии **War & Order** (`com.camelgames.superking`) на Android через ADB, компьютерное зрение и локальный OCR.

Проект развивается как песочница для RPA/CV-экспериментов: сначала — надёжное восприятие экрана и безопасная навигация, затем — городской цикл, сюжетные задания и бой.

### Как принимается решение

1. **Кадр** берётся из короткого кэша (`frame_ttl_sec`), чтобы не дёргать ADB на каждом такте.
2. **Классификатор** проверяет профили по приоритетам: якорные шаблоны → OCR-ключевые слова.
3. Для `city_view` дополнительно проверяется **яркость нижней навигации**: тёмная навигация означает модальное окно поверх города.
4. Если экран неизвестен, включается **watchdog**: ожидание, `Back`, затем полное восстановление (Home → запуск игры).
5. Перед действием задача обязана найти **шаблон** или уверенный OCR-элемент. Слепые клики по координатам в новых задачах запрещены.
6. После действия `ActionGuard` ждёт **ожидаемый шаблон** или его исчезновение. Если результат не подтверждён, это сбой, а не успех.
7. Повторяющиеся сбои задачи увеличивают её интервал (до 3×), чтобы бот не
   зацикливался на устаревшем шаблоне.

Подробный разбор сторонних репозиториев и матрица переносов:
[`docs/repo_analysis.md`](docs/repo_analysis.md).

## 🚀 Быстрый старт

### 1. Зависимости

Требуется Python 3.10+:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Устройство и ADB

Включите «Для разработчиков» и «Отладку по USB/Wi-Fi». Проверьте подключение:

```bash
adb devices
adb connect 192.168.31.156:39519
```

Если порт неизвестен:

```bash
python tools/find_adb_port.py
```

Порт Wi-Fi ADB меняется после перезагрузки. Актуальный адрес смотрите в
`adb devices` или в настройках беспроводной отладки. Если mDNS молчит,
бот сам сканирует диапазон 30000–50000 и подключается к найденному порту.

Параметры в `config.yaml`:

```yaml
device:
  adb_path: "C:\\platform-tools\\adb.exe"
  ip: "192.168.31.156"
  port: 39519
  frame_ttl_sec: 1.5
```

При старте бот закрепляет экран включённым (`keep_screen_on: true`):
`svc power stayon true`, `stay_on_while_plugged_in=3` и максимальный
`screen_off_timeout`. Это критично: когда экран гаснет, Wi-Fi ADB
отваливается, и разбудить устройство удалённо нельзя.

### 3. Проверка здоровья и восприятия

```bash
# Быстрая проверка: ADB, экран, игра, классификация, HUD
python tools/healthcheck.py

# То же в JSON + закрепить экран включённым
python tools/healthcheck.py --json --keep-awake

# Один снимок: экран, уверенность, HUD, OCR-текст
python tools/inspect_state.py --json

# С сохранением размеченного кадра
python tools/inspect_state.py --save logs/inspect/city.png
```

> `inspect_state.py` и `capture_template.py` не сохраняют кадр, если игра
> не на переднем плане. Это защита от попадания чужих данных в `logs/`.

Пример вывода:

```json
{
  "screen": "city_view",
  "confidence": 1.0,
  "source": "anchor",
  "evidence": "btn_nav_lord=1.00",
  "hud": {
    "energy": 100,
    "food": 128800,
    "wood": 110800,
    "power": 6044,
    "gold": 0,
    "gems": 130,
    "vip_level": 1
  }
}
```

### 4. Запуск бота

```bash
# Только наблюдение (ничего не нажимает)
python main.py --observe --duration 60

# Один снимок состояния и выход
python main.py --once

# Обычный режим (задачи из config.yaml)
python main.py
```

### 5. Тесты

```bash
python -m unittest discover -s tests -v
```

Сейчас **41 тест, OK**. Покрыты троттлинг и backoff задач, поиск нескольких
шаблонов (region/scale), пересъёмка устаревшего/тёмного кадра, таймеры
world model, разбор длительностей (`11:52` → 712 с) и полный офлайн-flow
улучшения здания. Локальный тест OCR эталонной панели пропускается, если
`logs/inspect/building_upgrade_wall.png` отсутствует.

## 🧪 Калибровка новых экранов

1. Откройте нужный экран вручную.
2. Сделайте снимок:

   ```bash
   python tools/inspect_state.py --save logs/inspect/screen.png
   ```

3. Вырежьте устойчивый элемент (заголовок, кнопку) в
   `assets/templates/<name>.png` **без анимационных бликов**:

   ```bash
   python tools/capture_template.py --frame logs/inspect/screen.png \
       --name title_my_screen --box 462 132 166 72 \
       --test logs/inspect/*.png
   ```

   `--test` покажет, не срабатывает ли шаблон на соседних экранах
   (score ≥ 0.75 — вероятное ложное срабатывание).
4. Добавьте профиль в `src/perception.py`:

   ```python
   ScreenProfile(
       state=GameState.MY_SCREEN,
       priority=25,
       groups=((Anchor("title_my_screen", 0.72, (0.2, 0.1, 0.8, 0.2)),),),
       keywords=("мой экран",),
   )
   ```

5. Проверьте на городе и соседних экранах, что шаблон не даёт ложных
   срабатываний. Порог 0.70–0.85 подбирается экспериментально.
6. Обновите `memory_bank/screens_manifest.md`.

## ⚠️ Известные ограничения

- Захват кадра ~1.9 с — приемлемо для города, но мало для боя.
- Полный OCR-проход ~2 с; поэтому OCR используется только как резерв.
- Уровень лорда (маленький бейдж под аватаром) пока не читается OCR.
- Часть шаблонов устарела после обновления UI; их нужно переснять.
- Аккаунт не в альянсе, поэтому альянс-задачи отключены.
- Бот не обходит защиту игры и не гарантирует отсутствие блокировок.
- **Приватность:** `logs/` исключён из git; инструменты калибровки не
  сохраняют кадр, если игра не на переднем плане. Не добавляйте в репозиторий
  скриншоты с данными аккаунта или других приложений.
