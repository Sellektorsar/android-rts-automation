# Банк памяти (Memory Bank) — War & Order Bot

Банк памяти — это структурированное хранилище знаний об интерфейсе, экранах,
координатах, переходах и проверенных сценариях игры *War & Order*. Он нужен,
чтобы не выяснять заново уже проверенные факты и не повторять старые ошибки.

## 📁 Содержимое

| Файл | Назначение |
|---|---|
| `current_state.md` | Оперативная сводка: устройство, включённые задачи, проверенные координаты, блокеры, ближайшие шаги. **Читать первым.** |
| `decisions.md` | Архитектурные решения (ADR): почему выбран pull-захват, один OCR, порог свежести 8 с, безопасное улучшение и т.д. |
| `screens_manifest.md` | Каталог состояний игры, визуальные якоря, кнопки, переходы, проверенные сценарии. |
| `ui_coordinates.yaml` | Машиночитаемые координаты и зоны интереса для 1080x2436. |
| `city_district.md` | Привязка построек квартала к кадрам камеры: эталонные виды, гомография SIFT REF→LIVE, инвентарь зданий с тап-точками и уровнями, план runtime-выравнивания. Читать при любой работе с координатами зданий. |
| `world_model.json` | Персистентное состояние аккаунта, строителей, таймеров, ресурсов и кэша координат. |
| `dialogs_and_lore.md` | Персонажи, главы кампании, подтверждённый сюжетный прогресс и открытые вопросы. |
| `development_log.md` | Краткая хронология изменений кода и проверок. |
| `reflections.json` | Runtime-журнал успехов/сбоев задач (создаётся ботом, не редактируется вручную). |

## 🔄 Правило обновления

**Перед работой:**
1. Прочитать `current_state.md`.
2. Открыть профильную карточку экрана в `screens_manifest.md`.
3. Проверить актуальные координаты в `ui_coordinates.yaml`.

**После нового экрана или сценария:**
1. Добавить карточку в `screens_manifest.md`: ID, якорь, кнопки, вход/выход,
   пост-условие.
2. Добавить/исправить координаты в `ui_coordinates.yaml`. Новые зоны задавать
   долями кадра; абсолютные координаты помечать как проверенные.
3. Если изменился прогресс аккаунта — обновить `world_model.json` только после
   подтверждения на экране.
4. Записать изменение и результат проверки в `development_log.md`.

**После изменения поведения:**
- Обновить `current_state.md` и, если решение архитектурное, `decisions.md`.
- Не коммитить `logs/` и скриншоты с данными аккаунта. В банке памяти хранятся
  описания и безопасные эталоны, а не личные данные.

## 🔐 Безопасность

- Никаких слепых кликов по координатам: только найденный шаблон или уверенный
  OCR.
- Зелёная кнопка гемов и любые кнопки оплаты не нажимаются.
- Диалог «Выйти из игры?» не подтверждается.
- Проект остаётся в образовательных/тестовых рамках: без модификации APK,
  памяти и сетевого трафика.
