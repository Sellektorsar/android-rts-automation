# Квартал построек — привязка к кадрам камеры

Обновлено: **2026-10-23**. Кадр 1080×2436, состояние `city_view`.

Файл нужен из-за **дрейфа камеры**: координаты зданий действительны только
для конкретного вида города. Здесь зафиксированы два эталонных кадра и
гомография между ними, чтобы при сдвиге камеры не тапать не по тем зданиям
(живой сбой 2026-10-23 — см. ADR-022).

## 🔧 План выравнивания (не реализован)

1. Хранить эталонный кадр квартала в игнорируемом пути и блок `alignment`
   в `config.yaml`: `enabled`, `reference`, `min_inliers`, `max_features`,
   `ransac_threshold`.
2. В `BuildingUpgradeTask` на свежем кадре считать SIFT-гомографию
   эталон → текущий кадр и переносить фиксированные точки через
   `cv2.perspectiveTransform` (статичный HUD/нижнюю навигацию маскировать).
3. **Без успешного выравнивания фиксированные точки не тапать** — пропуск,
   а не слепой клик (правило «только шаблон или уверенный OCR»).
4. Ключ паспорта держать по точке в **эталонном** кадре, чтобы сдвиг камеры
   не переключал статус `capped` на чужое здание.
5. Писать качество выравнивания (inliers, остаток) в лог задачи.

  поиска бейджей по цвету/тёмной цифре. Итог: насыщенный HSV-детектор ловит
  только золотые UI-иконки (14 срабатываний, почти все — HUD), OCR цифр 4×
  кропа не читается. **Бейджи пока читают человек/зум, не runtime-детектор.**
