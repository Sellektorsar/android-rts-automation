## ✅ Что работает

- Подключение, mDNS-поиск, скан портов, переподключение, перезапуск ADB.
- Pull-захват кадра (~1.8–1.9 с), кэш кадра, `frame_age()`.
- **Быстрый поток `FastCapture`**: `adb exec-out screenrecord --output-format=h264`
  → `ffmpeg` → BGR `540×1218`; живой замер **14.11 FPS** (30 кадров за 2.126 с),
  в статичном диалоге/бою — до **~44 FPS** (682 кадра за 15.2 с).
- Классификация экранов по якорям + OCR-резерв:
  `city_view`, `royal_road`, `alliance_menu`, `quests_menu`,
  `building_menu`, `building_upgrade`, `popup_offer`, `popup_generic`,
  `loading`, **`tutorial_battle`** (боевой экран).
- **Боевой экран**: якорь `battle_pause` `(62, 150)`; для быстрых кадров
  `540×1218` — отдельный `battle_pause_fast`.
- **Безопасный вход/выход из боя этапа 7**: брифинг → «Испытание» →
  диалог героизма (только зелёная кнопка) → бой → пауза → «Выйти» →
  карта кампании → город. Выход не открывает оплату и не требует
  подтверждения.
- HUD: энергия, еда, дерево, сила, золото, самоцветы, VIP.
- Безопасная навигация: возврат в город, штатная стрелка, диалог выхода.
- `ActionGuard`: свежесть, тёмный кадр, пересъёмка, ожидание шаблонов,
  стабильность, изменение области, подтверждение действия.
- Адаптивный backoff задач по истории сбоев.
- WorldModel: строители, таймеры, ближайшее событие, summary, кампания
  (глава/этап/брифинг) и `update_campaign()`.
- CityHarvest (grain/wood) и CityGifts (подарок торговца).
- QuestRewards: открывает ежедневные задания, нажимает **только** зелёную
  «Забрать награды», возвращается в город; премиальные кнопки не трогает.
- BuildingUpgrade: полный flow улучшения, OCR названия/уровней/таймера,
  запись подтверждённого таймера в WorldModel.
- **Шаблонные точки зданий** (`building_forge`, `building_hospital`,
  `building_wall_gate`): здание ищется мультимасштабно на свежем кадре,
  тап = центр шаблона + `tap_dy × scale`. Радиальное «Улучшить» тоже
  ищется мультимасштабно (живой кадр: 0.794 при scale 0.9) — и в
  основном flow, и в probe. У каждого шаблона свой порог
  (`SPOT_TEMPLATE_THRESHOLDS`): forge 0.80, hospital 0.85,
  wall_gate 0.75 — красные церкви дают ложные совпадения госпиталя
  ~0.65–0.75.
- **Живой поиск кузницы 2026-10-23**: `building_forge` conf 0.923@1.0 →
  тап (528,621) → «Улучшить» (388,825) conf 0.794@0.9 → панель
  «Кузница» LV.5→LV.6, timer 1188 c, требуется Замок 6 ур. (сейчас 5) →
  синяя кнопка серая, не нажата → возврат в город. Кузница LV.5 готова,

  conf 0.764@0.98, полный flow сработал: «Улучшить» 0.798 → панель

## 🚧 Блокеры и ограничения

- **ДРЕЙФ КАМЕРЫ (P0, 2026-10-23)** — фиксированные координаты спотов
  действительны только для конкретного вида города. Живое доказательство:
  точка `tent 590,1350` в 05:27 улучшила палатку LV.4→LV.5, а в 05:45
  прочитала LV.1→LV.2 (после сдвига камеры тап ушёл в другое здание); все
  фиксированные точки после 06:10 промахивались. Паспорта при этом молча
  переписываются чужими уровнями. Решение (SIFT-выравнивание кадра, пропуск
  точки без выравнивания, ключ паспорта по эталонному кадру) — ADR-022;
  гомография получена (744 инлаера, точность ~1–3 px), **в код задачи ещё не
  перенесена**. Инвентарь и привязка кадров — `city_district.md`.
- **Типы зданий в `config.yaml` и паспортах неполные** — имена `farm` /
  `sawmill` / `tent` / `camp` это метки точек, а не тип: `pt:farm:750,1080`
  живым тапом оказался «Лесопилкой», `pt:farm:700,1240` теперь попадает в
  новое здание LV.1, четыре последних спота (786,1430), (968,1520),
  (812,1705), (787,1870) не открывают ни одного здания (берег, вода, пустая
  площадка). Авторитетен только OCR баннера радиала и заголовка панели
  (ADR-023).
- **Автоматического детектора бейджей уровня нет**: HSV по золоту ловит
  иконки HUD, OCR цифры с 4× кропа не читается. Уровни по бейджам читает
  человек/зонд, в рантайме — только OCR панели.
- **Для снятия выделения нельзя тапать по небу/морю**: тап (1000,700) открыл
  событийную модалку «Уровень Замка должен быть 15» с синей «Вперёд»
  (закрыта Android `Back`, `city_view` вернулся).
- Стена Замка уже `LV.5` при замке `LV.5`; следующий уровень может требовать
  более высокого замка/лорда. Для живой проверки `BuildingUpgrade` нужно
  найти другое доступное здание.
- ~~Мистика стены (тапы тела/купола башни не открывали меню)~~ **РЕШЕНО
  2026-10-22**: кликабельна подошва/база башни; проблема была в узкой области
  поиска кольца. Слоты кольца вращаются вокруг здания
  (`(639,1500)→(590,1358)`, `(710,1610)→(584,1382)`, `(476,1379)→(577,1374)`).
  `_radial_region(center)` теперь щедрая (`cx±0.20W`, `cy-0.28H..cy+0.05H`).
  Task `enabled: false` (стена LV.5, недоступна апгрейду); задача умеет
  безопасно пропускать неактивные подтверждения.
- Нижний баннер города показывает **«Вызов Спасителя порядка, этап 7 (0/1)»**;
  экран Королевской Дороги подтвердил главу **4 «Вербовка Войск I»**.
  `current_chapter=4` корректно, `current_chapter_title` заполнен.
- «Вперёд» этапа 7 закрывает окно и возвращает в город; вход на карту —
  через основание портала. Боевой цикл этапа 7 подтверждён отдельным
  зондом `probe_stage7_combat.py --confirm`.
- **Камера города ушла (хуже после эксперимента):** текущий кадр
  `logs/inspect/after_revert.png` не содержит настоящего `portal_campaign`
  (совпадение `0.55` — ложное, на синей крыше). Попытка pinch-out/pinch-in
  через motionevent не восстановила исходный вид. Портал вне экрана,
  игра остаётся в `city_view`. Нужна **ручная** установка камеры
  (pinch/pan) до появления синей арки портала в нижней части экрана;
  автономный camera-reset не реализован.
  Позже камера снова изменилась: общий отдалённый вид замка
  (`logs/inspect/city_check_now.png`). Мультимасштабный поиск шаблона
  портала (масштабы 0.30–1.0) даёт максимум `0.67` — ложные совпадения
  на небе/горе; южная кромка города просмотрена отдельно. Вероятно,
  портал скрыт панелью чата/навигации или вне вида к югу; endpoint ADB
  снова сменился (`40655`, discovery подобрал автоматически).
  **Снят вручную (2026-10-22)**: камера сдвинута к югу вручную, портал
  появился на `(452, 1766)` при масштабе `1.15`. Поиск portal_campaign
  теперь мультимасштабный (0.70–1.20, `Vision.find_template_multiscale`);
  dry-run и два живых боя с новой камерой прошли штатно
  (`stage7_dryrun_multiscale.log`, `stage7_combat_skilltest*.log`).
  Вывод: камера города нестабильна между сессиями — перед боем всегда
  полагаться на мультимасштабный поиск, при отсутствии совпадений не
  предпринимать действий.
- **Оверлей навыка в двух последних боёx не появился** (герой, видимо,
  уже повышен): живой тест «карточка → Подтвердить» по-прежнему ожидает
  появления оверлея; обработчик офлайн-проверен.
- Боевой автопилот не реализован: есть распознавание боя, безопасный
  вход/выход и обработчик выбора навыка (офлайн-проверен). Управление
  джойстиком, победа/поражение и повтор этапа — следующие задачи.
- ~~`FastCapture`: недетект боя/зависание чтения~~ **решено**: reader
  thread держит только свежий кадр, probe сливает устаревшие кадры перед

  `battle_pause_fast` `0.99`, `52 FPS`, `0.0 с`; `pull_fallback` больше
  не понадобился. Остался автоперезапуск после `--time-limit`.
- Ежедневный вход/события при восстановлении могут дать `unknown`.
  `btn_close_event_x` добавлен, но ежедневную награду (`Забрать награды`
  `(540, 1657)`) зонд пока не закрывает автоматически.

- Нет шаблонов `bubble_stone`, `bubble_iron`, `bubble_wishing_well`.
- `android-harness` daemon на Unix-socket не подходит для Windows.
- `esp32-android-agent` HID-часть требует аппаратного ESP32.

## 📏 Правила

- Не кликать вслепую по координатам: только по шаблону или уверенному OCR.
- В бою выходить только по шаблону `btn_battle_exit`; OCR путает
  «Выжить в течение…» с «Выйти».
- В диалоге героизма нажимать только зелёное «Испытание»; синее
  «Укрепление героизма» не трогать.
- Не нажимать зелёную кнопку гемов и любые кнопки оплаты.
- Не подтверждать «Выйти из игры?».
- Не коммитить `logs/` и скриншоты с данными аккаунта.
- После нового экрана — карточка в `screens_manifest.md` и координаты в
  `ui_coordinates.yaml`.
- После изменения поведения — запись в `development_log.md`.
